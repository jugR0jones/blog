# Repository Guidelines

`F:\Experiments` is a personal experiments monorepo: each top-level folder is a standalone project with its own solution file, CMake tree, or Unity project. There is no shared root build, and the Git history is currently empty, so the conventions below are the agreed defaults.

## Project Structure

- .NET solutions: `AddTranslation`, `AdventOfCode2025`, `DesignPatterns`, `Drivetrain`, `FBXDiff`, `FixedWidthString`, `LibSDL`, `PooledBuffers`, `RipDir` — each has a `<Name>.sln`; source lives in the main project, tests in a sibling `<Name>.Tests` project.
- Unity 2022.3.30f1: `OffroadArena` (mobile game) and `VammasPSB5500-5_KDFW` (ATC sim, GameFrame/Zenject). Game code lives under `Assets/`; `.csproj` files are auto-generated by Unity.
- C++/CMake: `Game` (engine/game/tools split) and `VTrio.Net` (VirtualTRIO).
- Legacy/archived: underscore-prefixed folders (`_GameEngine`, `_GameEngineV2`, `_FridayTalkGameEngine`) are older iterations — treat as read-only reference unless asked to modify them.
- Subproject `AGENTS.md` files (e.g., `OffroadArena/AGENTS.md`, `_GameEngineV2/AGENTS.md`) take precedence over this file within their folders.

## Build, Test, and Development Commands

- `dotnet build <proj>\<Name>.sln` — build a solution.
- `dotnet test <proj>\<Name>.Tests\<Name>.Tests.csproj` — run a project's NUnit tests.
- `dotnet run --project <path>` — run an executable (e.g., `AddTranslation/AddTranslation.CLI`).
- `LibSDL`: run `dotnet tool restore` first (it ships a `dotnet-tools.json`), then `Generate.ps1`.
- Unity projects: open via Unity Hub with `2022.3.30f1`; never `msbuild` the generated `.csproj` files.
- C++: standard CMake flow per project, e.g., `cmake -B build -S Game`.

## Coding Style & Naming Conventions

- C#: 4-space indentation, no tabs. New projects enable `ImplicitUsings` and `Nullable`; use `LangVersion latest` where the project sets it.
- Naming: PascalCase types and members, camelCase locals, `_prefix` private fields. Test projects are named `<Name>.Tests.csproj`; Unity test assemblies use `<Name>.Tests.EditMode` / `<Name>.Tests.PlayMode` suffixes.
- C++: follow each project's existing style; there is no root formatter.

## Testing Guidelines

- .NET: NUnit via `NUnit3TestAdapter` + `Microsoft.NET.Test.Sdk` (NUnit 3 or 4 depending on project). Test class names mirror the unit under test; test methods describe the expected behavior.
- Unity: Unity Test Framework with EditMode and PlayMode assemblies; run via Window → General → Test Runner.
- Run the affected project's tests before committing; keep builds green.

## Commit & Pull Request Guidelines

- No Git history exists yet. Use concise imperative subjects scoped to the project folder, e.g., `Drivetrain: fix axle torque curve`.
- Pull requests: describe the change, list affected project folders, and note Unity version implications for Unity work; include screenshots for UI changes. Keep PRs to one project where possible.
